## Результати експериментів

### 1. Експеримент з автоекрануванням (Урок №1)
При додаванні товару з назвою `<script>alert(1)</script>` у базу даних, на сторінці `/products/` скрипт не виконався у браузері, а вивівся як звичайний текст `&lt;script&gt;alert(1)&lt;/script&gt;`.  
**Висновок:** DTL (Django Template Language) автоматично екранує всі змінні, що запобігає XSS-атакам.

### 2. Експеримент із відключенням DEBUG (Урок №4)
При зміні `DEBUG = False` у `settings.py` сторінка втратила стилі CSS.  
**Висновок:** Вбудований web-сервер розробки Django за замовчуванням обробляє та віддає static-файли лише за умови `DEBUG = True`. У продакшені для цього використовуються окремі вебсервери (наприклад, Nginx/WhiteNoise).

### 3. Експеримент із CSRF-захистом (Урок №5)
При видаленні тегу `{% csrf_token %}` із форми додавання товару при спробі відправки POST-запиту виникла помилка `403 Forbidden (CSRF verification failed)`.  
**Пояснення причин (чому запит відхилено):**  
Django містить вбудований middleware захисту від CSRF (Cross-Site Request Forgery). При надсиланні POST-запиту сервер очікує у тілі форми унікальний секретний токен, який відповідає значенню в cookie браузера користувача. Якщо цього токена немає у формі або він не збігається, Django відхиляє запит як потенційну атаку з боку сторонніх сайтів.
